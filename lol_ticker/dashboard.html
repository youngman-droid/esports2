Calibration

Each settled market contributes its last price before the cutoff (YES terms) vs. its resolution. Polymarket: only conditions where both outcome tokens have a pre-cutoff price are included — one-sided sampling is winner-biased and fabricates miscalibration. Kalshi: prices are bid/ask midpoints (trade-less candles close at the bid, which fakes longshot bias). Use the filter (e.g. "match", "map 1") to slice by market type. Point size ∝ sample count. "After start" horizons approximate post-draft odds: LoL drafts run ~10–15 min past scheduled start (plus delays), so they're most meaningful filtered to game-1 / match markets — for map 2+ markets the offset lands mid-series, not post-draft.

Draft analysis

Per-map winner markets matched to Oracle's Elixir game data. For each game, a team's win odds are sampled 16 min before actual game start (pre-draft) and 2 min after (post-draft); Δ draft is the market's re-rating after seeing the draft, in probability points. post-edge = actual wins minus post-draft odds (did reality beat the market's read of the draft). Games covered by both platforms count once.

Odds-free evaluation (outcome models)

No market data here. Event WPA: an in-game win-probability model fitted on gol.gg game states (gold / kill / tower / dragon / baron / inhib / herald / grub / atakhan / plate diffs, game time, side, Elo prior) against who actually won; each event's value is model WP after minus before. Draft (outcome model): logistic regression of who won on an Elo prior plus draft features over all Oracle's Elixir games; a team's draft edge is how much its drafts move model win probability beyond team strength. Both sit next to the market-based numbers above for cross-checking.

Draft simulator

Walks the competitive draft order (3+3 bans, 6 picks, 2+2 bans, 4 picks). Each action's effect is estimated by a ridge model fit on the market's post-draft re-rating across all matched games — own/enemy picks, own/enemy bans, same-team synergies, and cross-team matchups. Set blue's pre-draft win probability, then fill champions in order; the running estimate updates after every action. Champion names follow Oracle's Elixir spelling (autocomplete). Picks take an optional role (top/jng/mid/bot/sup) and the patch selector applies champion×patch meta effects; both are deviations on top of the base champion effect, so leaving them blank falls back to the base. Grey "unseen" = champion not in the training data (no effect).
